# 현재 작업

## 상태

계획 수립 완료 (1차 하네스 실전 테스트용으로 범위 축소). 구현 전 사용자 승인 대기 중 (Claude는 Planner/Reviewer만 수행, 코드 미변경).

## 1. 목표

대시보드(`pages/0_대시보드.py`) 우측 "시스템 상태" 영역의 표현 방식만 `st.metric` 나열에서 ROI / 이벤트 이미지 / 샘플 영상 3개 카드형 레이아웃으로 바꾼다. **개수를 세는 기존 로직, 값 자체, 판정·저장 로직은 전혀 건드리지 않고, 같은 3개 숫자를 카드 모양으로만 다르게 보여준다.** 썸네일·미리보기·캐싱·신규 파일은 이번 작업 범위에서 제외한다.

## 2. 현재 상태

- `pages/0_대시보드.py`의 `col2`(우측 열)는 `os.listdir()`로 개수를 센 뒤 `st.metric` 3개(저장된 ROI, 저장된 이벤트 이미지, 샘플 영상 파일)로 표시 중.
- 이 개수 계산 코드(`roi_count`, `event_count`, `data_count` 3줄)는 그대로 재사용하고, 그 값을 렌더링하는 `st.metric` 부분만 카드형 마크업/레이아웃으로 교체한다.

## 3. 구현 계획 (축소된 범위)

1. `col2` 내부의 기존 개수 계산 3줄(`roi_count`, `event_count`, `data_count`)은 **수정 없이 그대로 유지**한다.
2. 그 아래 `st.metric` 3개를 3개의 카드 UI로 교체한다 — 예: `st.container(border=True)` 또는 동등한 Streamlit 기본 컴포넌트로 카드 박스를 만들고, 그 안에 아이콘/라벨 + 기존 변수 값(개수)을 표시한다.
3. 썸네일 이미지, ROI 미리보기(다각형 그리기), 영상 첫 프레임 추출은 **만들지 않는다**.
4. 이 작업을 위한 신규 헬퍼 파일은 만들지 않는다 — 카드 렌더링 코드는 `pages/0_대시보드.py` 안에 그대로 둔다.
5. `core/*.py` 파일은 전혀 수정하지 않는다 (읽기 호출조차 새로 추가하지 않음 — 기존에 쓰던 `import` 외 변경 없음).
6. `st.cache_data` 등 캐싱 로직은 추가하지 않는다 (캐시가 필요할 만큼 무거운 연산이 없는 범위이므로).
7. `col1`(개요/사용법/위험판단 규칙 표)과 페이지 하단 안내문(`st.info`), "기술 스택" 문구는 그대로 둔다.
8. 개수가 0인 경우에도 기존과 동일하게 "0개"로 표시되면 충분하며, 별도의 빈 상태 문구를 새로 만들 필요는 없다(기존 동작 그대로).

## 4. 수용 기준 (축소된 범위)

- `pages/0_대시보드.py` 외의 파일은 변경되지 않는다 (`git diff` 기준 이 파일 하나만 변경).
- `roi_count`, `event_count`, `data_count`를 계산하는 코드 로직은 이번 변경 전후로 동일하다(계산식·조건 변경 없음).
- 화면상 ROI / 이벤트 이미지 / 샘플 영상 3개 항목이 각각 구분된 카드 형태(테두리/박스 등 시각적 구획)로 보이고, 카드 안에 라벨과 기존과 동일한 개수 값이 표시된다.
- 썸네일·이미지 미리보기·ROI 다각형 미리보기가 추가되지 않는다.
- `core/` 이하 파일은 `git diff`상 변경 사항이 전혀 없다.
- 모니터링 / ROI 설정 / 이벤트 다시보기 / 성능 평가 등 다른 페이지와 AI 감지·ROI 판정·이벤트 저장 동작은 이번 변경 전과 완전히 동일하게 유지된다.
- 새로 추가된 파일이 없다(`git status`상 신규 파일 없음, 수정된 파일만 존재).

## 5. 예상 변경 파일

- `pages/0_대시보드.py` (유일한 변경 대상 — `col2`의 `st.metric` 3개를 카드 UI로 교체)
- `docs/tasks/current.md` (계획 및 진행 기록 갱신)

## 6. 파일 소유권

| 파일 | 소유자 | 상태 |
|---|---|---|
| pages/0_대시보드.py | Codex (구현/테스트) | 계획 승인 대기 |
| docs/tasks/current.md | Claude (계획/리뷰) | 계획 작성 완료, 구현 후 리뷰 예정 |

Claude는 계획 수립과 구현 후 리뷰만 수행하며 `pages/0_대시보드.py`는 직접 수정하지 않는다. Codex 구현 전, 사용자 승인 없이는 착수하지 않는다.

## 7. 위험 요소 또는 주의사항

- 범위를 카드 레이아웃 표현으로만 한정했으므로, 구현 중 "이왕이면 썸네일도" 식으로 범위가 자연 확장되지 않도록 주의한다(이번 승인 범위 밖).
- `st.container(border=True)` 등 사용 중인 Streamlit 버전에서 지원하지 않는 컴포넌트를 쓰지 않도록 버전 확인이 필요하다 — 미지원 시 `st.columns`+마크다운 조합 등 구버전 호환 카드 표현으로 대체한다.
- 개수 계산 3줄(`roi_count`, `event_count`, `data_count`)의 위치를 옮기더라도 계산 조건(`os.path.exists` 체크, 확장자 필터 등)은 문자 그대로 유지해야 한다 — 리팩터링 삼아 조건을 "개선"하지 않는다.
- 이번 변경은 `config.py`의 판정 임계값·탐지 클래스와 무관하며 건드리지 않는다.

## 구현 결과

- 실제 변경 파일:
  - `pages/0_대시보드.py`
  - `docs/tasks/current.md`
- 주요 변경 내용: 기존 `roi_count`, `event_count`, `data_count` 계산식을 그대로 유지하고, 세 개의 `st.metric` 표시만 각각 `st.container(border=True)` 안의 라벨과 개수 표시로 교체했다. 썸네일, ROI 프리뷰, 캐싱, 신규 헬퍼 또는 신규 파일은 추가하지 않았다.

## 테스트 결과

- 실행한 테스트:
  - Python `ast.parse`로 `pages/0_대시보드.py` 문법 검사
  - `git diff --check`로 공백 오류 검사
  - `git diff -- pages/0_대시보드.py`로 변경 범위와 집계식 보존 확인
  - `git diff -- core`로 `core/` 무변경 확인
  - `rg`로 세 집계식 유지 및 `st.metric`, 캐싱, 썸네일 관련 코드 미추가 확인
- 테스트 결과: 모든 정적 검증 통과. `git diff --check`는 줄 끝 형식이 향후 LF에서 CRLF로 바뀔 수 있다는 경고만 출력했고 오류 없이 종료했다.
- 수용 기준 충족 여부: 정적 기준 충족. 대시보드 파일 외 애플리케이션 코드 변경 없음, 세 집계식 보존, 세 개의 독립 카드와 라벨·개수 표시 구현, 금지 기능 및 신규 파일 미추가, `core/` 무변경을 확인했다.
- 미실행 항목과 사유: Streamlit 브라우저 화면의 실제 렌더링은 실행 시 런타임 데이터나 디렉터리에 영향을 줄 수 있어 이번 최소 변경 검증에서는 실행하지 않았다.
